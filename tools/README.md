# generate_chapter.py

A local command-line tool that turns a page range of a textbook PDF into a
new UPSC-level-only chapter in the [UPSC Prep app](https://dhananjay09.github.io/upsc-prep-app/),
following the exact same process used to build the Geography chapters so far:
extract → generate grounded UPSC questions → split into 10-question tests →
merge into `subject_data.json` → rebuild the app → validate → commit & push.

## One-time setup

```bash
git clone git@github.com:dhananjay09/upsc-prep-app.git
cd upsc-prep-app
pip install anthropic pymupdf --break-system-packages   # or inside a venv
export ANTHROPIC_API_KEY="sk-ant-..."                    # console.anthropic.com
```

You also need **Node.js** installed (only used to rebuild `app/index.html`
and sanity-check the JavaScript afterwards), and `git` configured to push to
the repo without prompting (SSH key on GitHub, or a saved HTTPS credential).

If this is a brand new machine, git also needs to know who you are:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

Copy `generate_chapter.py` into the root of your `upsc-prep-app` clone (or
anywhere — you can pass `--repo-dir` to point at the clone).

## Running it

```bash
python3 generate_chapter.py \
  --pdf "/path/to/CERTIFICATE IN PHYSICAL AND HUMAN GEOGRAPHY 3ed..pdf" \
  --start-page 49 --end-page 58 \
  --subject geography \
  --chapter-title "Weathering, Mass Movement and Groundwater" \
  --source-dir source_material/goh_cheng_leong_geography
```

- `--start-page` / `--end-page`: page numbers exactly as shown in your PDF
  viewer (1-indexed, inclusive on both ends).
- `--subject`: the key in `subject_data.json` — `geography`, `polity`,
  `economy`, or `history`.
- `--chapter-title`: human-readable title shown in the app.
- `--chapter-id`: optional; auto-generated by slugifying the title if
  omitted (e.g. "Weathering, Mass Movement and Groundwater" →
  `weathering_mass_movement_and_groundwater`).
- `--source-dir`: optional folder to save the raw extracted text and
  generated question JSON for provenance, matching how earlier chapters
  were archived in the repo.
- `--pending-title`: only needed if the wording in the subject's "coming
  soon" pending list doesn't exactly match `--chapter-title`.

By default the script commits **and pushes** to `origin` when it finishes.
Add `--dry-run` if you'd rather review the result locally first (open
`app/index.html` in a browser and try the new chapter's quiz), then either
re-run without `--dry-run` or just `git push` yourself.

## What it does, step by step

1. Extracts and cleans the text from the given page range (strips stray
   page-number lines, collapses excess blank lines).
2. Sends that text to Claude in batches, asking for real UPSC-Prelims-level
   questions — statement-based, assertion-reason, and match-the-following
   formats — strictly grounded in the supplied text, with rich explanations.
   It keeps asking for more, telling the model what's already been written
   each time, until a sensible cap is hit or the well runs dry (typically
   35–70 questions depending on how content-rich the chapter is).
3. Validates every question (4 options, valid answer index) and removes
   exact and near-duplicate questions.
4. Splits the final list into `test1`, `test2`, ... of 10 questions each
   (the last test can be smaller/larger to avoid a tiny leftover group).
5. Adds (or replaces, if `--chapter-id` already exists) the chapter in
   `subject_data.json`, and removes the matching title from that subject's
   `pending` list if present.
6. Rebuilds `app/index.html` and `upsc-prep-app.html` from
   `app_template.html`, and validates the resulting JavaScript actually
   parses before committing anything.
7. Commits everything (`subject_data.json`, the rebuilt HTML files, and the
   source-material files if `--source-dir` was given) and pushes.

## Tips

- Run with `--dry-run` for your first chapter or two until you're
  comfortable with the output quality, then drop it once you trust the flow.
- If a chapter comes out too thin (the source pages are short), that's
  expected — the script stops asking for more once new, non-redundant,
  well-grounded questions stop coming.
- To regenerate a chapter you're not happy with, just re-run with the same
  `--chapter-id` — it replaces the existing entry rather than duplicating it.
- `--no-rebuild` skips the app-rebuild/push step entirely if you want to
  batch up several chapters' `subject_data.json` changes before rebuilding
  and pushing once.
